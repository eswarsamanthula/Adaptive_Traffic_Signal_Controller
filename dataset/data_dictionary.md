# Data Dictionary

Adaptive Traffic Signal Controller — dataset reference.

Source workbook: `adaptive_traffic_project_dataset.xlsx` (SYNTHETIC data,
generated by a seeded simulation, seed 2026 — not measured traffic). All
sheets share one clock: **2026-10-12 03:00:00 → 23:49:00**.

---

## Traffic_Data  →  `traffic_data.csv`

Purpose: the adaptive-run traffic demand and state, one row per approach per
1-minute interval (Timestamp + Approach is the key).

| Column | Type | Unit | Description |
| --- | --- | --- | --- |
| Timestamp | datetime | yyyy-mm-dd hh:mm:ss | Start of the 1-minute interval. Key: Timestamp + Approach. |
| Approach | text | - | North, South, East or West. |
| Vehicle_Count | integer | vehicles | Vehicles in the detector zone at the end of the interval: Queue_Length + vehicles discharged in the last 10 s. |
| Queue_Length | integer | vehicles | Vehicles waiting at the stop line at the end of the interval. |
| Avg_Wait_Time | integer | seconds | Mean time the currently queued vehicles have waited, at the end of the interval. |
| Arrival_Rate | integer | vehicles/minute | Vehicles that arrived during the interval. Exogenous demand, not affected by signals. |
| Congestion_Level | text | - | LOW / MEDIUM / HIGH (see rule below). |
| Scenario | text | - | Whole-intersection condition; identical on all 4 rows of a Timestamp. |

---

## Signal_Cycle  →  `signal_cycle.csv`

Purpose: the adaptive controller's actual signal-state events (what the signal
ran), one event per row. Event_ID sequence E000001….

| Column | Type | Unit | Description |
| --- | --- | --- | --- |
| Event_ID | text | - | Unique ID of one signal-state event (E000001…). Adaptive run. |
| Cycle_No | integer | - | Signal cycle number (1…). Links to Adaptive_Decisions. |
| Approach | text | - | Approach the event belongs to. |
| Start_Time | datetime | yyyy-mm-dd hh:mm:ss | Exact start of the event, computed from the cycle schedule. Each event starts when the previous ends. |
| Signal_State | text | - | GREEN, YELLOW or ALL_RED. Only one approach has an event at a time. RED is not stored as rows: while one approach is GREEN, YELLOW or ALL_RED, the other three are RED. |
| Duration_sec | integer | seconds | GREEN = Applied_Green_Time (10–60), YELLOW = 3, ALL_RED = 2. ALL_RED is the 2 s clearance interval after that approach's yellow, during which all four approaches show red. |

---

## Adaptive_Decisions  →  `adaptive_decisions.csv`

Purpose: the controller's timing decision per approach per cycle (why each
green was chosen). Key: Decision_ID + Approach. One decision per cycle
(D0001…), shared by that cycle's 4 rows.

| Column | Type | Unit | Description |
| --- | --- | --- | --- |
| Decision_ID | text | - | One decision per cycle (D0001…); shared by that cycle's 4 rows. Key: Decision_ID + Approach. |
| Cycle_No | integer | - | Cycle that the decision's applied timings generate in Signal_Cycle. |
| Decision_Time | datetime | yyyy-mm-dd hh:mm:ss | Time the decision was made = start of the cycle it controls. |
| Approach | text | - | Approach the timing applies to. |
| Traffic_Timestamp_Used | datetime | yyyy-mm-dd hh:mm:ss | Timestamp of the Traffic_Data reading used: the latest interval completed before Decision_Time (60–119 s old). Blank only in cycle 1 (startup default, no reading yet). |
| Queue_Length | integer | vehicles | Queue_Length copied from that Traffic_Data row. Blank in cycle 1. |
| Arrival_Rate | integer | vehicles/minute | Arrival_Rate copied from that Traffic_Data row. Blank in cycle 1. |
| Previous_Green_Time | integer | seconds | Applied green of the previous cycle (25 s for cycle 1). |
| Requested_Green_Time | integer | seconds | Controller's raw proposal before any safety limit. Can fall outside 10–60 s (observed 2–98 s). Not the signal that was run; see Applied_Green_Time. |
| Applied_Green_Time | integer | seconds | Safety-limited value actually used: Requested_Green_Time clamped to 10–60 s. Matches the green in Signal_Cycle for the same Cycle_No and Approach. |
| Cycle_Length_sec | integer | seconds | Sum of the 4 applied greens + 4 × (3 s yellow + 2 s all-red). Varies 80–208 s. |
| Decision_Reason | text | - | Extend / shorten (change of 3 s or more), hold, clamped to limit, or startup default. |

## Fixed_Baseline_Signal  →  `fixed_baseline_signal.csv`

Purpose: the fixed-time comparison schedule (baseline), one event per row.
Same columns as Signal_Cycle; fixed 25 s green, 3 s yellow, 2 s all-red,
120 s cycle, event IDs B000001…, from 03:00:00.

| Column | Type | Unit | Description |
| --- | --- | --- | --- |
| Event_ID | text | - | Unique ID of one baseline signal-state event (B000001…). |
| Cycle_No | integer | - | Signal cycle number (fixed 120 s cycle). |
| Approach | text | - | Approach the event belongs to. |
| Start_Time | datetime | yyyy-mm-dd hh:mm:ss | Start of the event; each event starts when the previous ends. |
| Signal_State | text | - | GREEN, YELLOW or ALL_RED. RED is implied for the other three approaches. |
| Duration_sec | integer | seconds | Fixed: GREEN = 25, YELLOW = 3, ALL_RED = 2. |

## Shared rules

**Congestion_Level** — the worse of: Queue_Length (LOW < 8, MEDIUM 8–15,
HIGH ≥ 16 vehicles) and Avg_Wait_Time (LOW < 30 s, MEDIUM 30–59 s, HIGH ≥ 60 s).

**Scenario** — describes the whole intersection per timestamp, not an approach:
Low traffic (03:00–06:59, 20:00–23:49), Rush hour (morning peak 07:32–09:58
heavy North; evening peak 16:24–19:06 heavy West), Sudden congestion
(13:00–13:19, surge on South), Uneven load (15:00–15:40, heavy East only),
Normal otherwise.

**Startup records (Cycle 1)** — Decision_ID D0001 rows (Cycle_No 1,
Decision_Time 2026-10-12 03:00:00) have blank Traffic_Timestamp_Used,
Queue_Length and Arrival_Rate because no completed traffic reading exists at
simulation start. The blanks are intentional; no measurements were invented.

**Closed loop** — Traffic_Data is the adaptive run: each decision uses
readings from Traffic_Data, its applied greens create Signal_Cycle, and those
signals change later queues and waits. Arrival_Rate is independent of signals.
