A software-based traffic simulation
01 · Introduction

Fixed timing meets changing demand

  • Fixed-time signals use preset timings.
  • Traffic demand changes throughout the day.
  • A fixed green may not match the current queue.
  • Uneven demand can raise waiting time and queue length.
Problem statement

How can a traffic signal use incoming traffic information to allocate green time more appropriately across four approaches — while monitoring command execution?

03 · Existing vs Proposed

Fixed-time vs adaptive simulation

Fixed-time approachProposed adaptive simulation
Preset green durationsGreen-time request based on measured demand
Does not react directly to the current queueUses queue length, arrival rate and waiting time
Limited visibility into controller eventsDashboard and database record system activity
Timing not tied to actuator acknowledgementSimulated commands checked using acknowledgements
Key idea: use current simulated traffic demand to request more suitable signal timings.

13 · Safety

Closed-loop evaluation & safety

Normal operation

37/37 phase acknowledgements accepted · zero violations on successful paths

Stop & Reset

4/4 unique RED commands acknowledged on each successful operation

Fault injection

Withheld ACKs → failed / unconfirmed. GREEN restart stays inhibited.

RUNNING→STOP / RESET→4 × RED→4 × ACK→CONFIRMED SAFE
Missing ACK→UNCONFIRMED · RESTART INHIBITED

200 automated tests passed, 0 failed. Software test results — not a real-world safety certification.

16 · Wrap-up

Conclusion, limitations & next steps

Achievements
  • End-to-end IoT-style traffic simulation
  • Demand-based green-time calculation
  • MQTT, Node-RED, SQLite and dashboard integrated
  • Offline ML and closed-loop ACK evaluation
  • Stop/Reset ACK handling and restart inhibition verified
Limitations
  • Simulation only — no physical sensors or lights
  • Team-prepared dataset; original source unavailable
  • Simplified simulation, not field measurements
  • ACK timing excludes real network delays
  • No fuel or emission measurements
Future work
  • Real sensors and hardware-in-the-loop
  • Recover dataset references
  • Validate on real junction data
  • Improve HIGH-traffic detection
  • Test network delays and failures
  • Study fairness and max red wait
